Keep in mind that code comments must follow the following rules:
 - Don’t comment anything an expert developer can understand by skimming the code.
 - Explain non-obvious why: intent, constraints, trade-offs, or rejected alternatives — not what the code does.
 - Comment surprising behaviour, hidden assumptions, or hazards that could otherwise cause incorrect changes or usage.
 - Keep comments concise, local, and accurate; update or remove them when the code changes.
 - Avoid mentioning constant values or numbers/detail of the code in a comment, when the code changes the comment will be wrong.

A similar philosophy should be taken with project documentation, capture the semantics, summaries and additional context,
but avoid talking about specific detail that might change later where possible.
